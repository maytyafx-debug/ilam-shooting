# METATYA Sports OS — Next.js pilot application

این برنامه، نسخه اجرایی اولیه و ماژولار METATYA Sports OS است. پایلوت فعلی برای **مدیریت اداری تیراندازی ورزشی در ایلام** تنظیم شده است؛ این نسخه هنوز سامانه کامل عملیاتی هیئت یا محصول آماده استفاده با اطلاعات واقعی ورزشکاران نیست.

## نیازمندی‌ها
- Node.js 20.9 یا جدیدتر
- npm
- پروژه Supabase متصل به برنامه و دارای جدول‌های فعال `public.sports_*`
- حساب Auth که عضویت فعال و نقش مجاز در سازمان داشته باشد

## راه‌اندازی در Termux
از پوشه مخزن:

```bash
cd ~/ilam-shooting/sports-os
cp .env.example .env.local
```

مقادیر واقعی پروژه را در فایل محلی `.env.local` قرار دهید، سپس:

```bash
npm install
npm run dev
```

برنامه در `http://localhost:3000` اجرا می‌شود.

برای کنترل و build:

```bash
npm run typecheck
npm run test:security
npm run test:demo
npm run lint
npm run build
```

یا همه آزمون‌های تعریف‌شده:

```bash
npm test
```

## متغیرهای محیطی

- `NEXT_PUBLIC_SUPABASE_URL`: آدرس پروژه Supabase
- `NEXT_PUBLIC_SUPABASE_ANON_KEY`: کلید عمومی anon یا publishable همان پروژه

**هرگز** کلید `service_role`، کلید secret، رمز دیتابیس یا JWT secret را در متغیرهای `NEXT_PUBLIC_*`، فایل‌های مخزن یا مرورگر قرار ندهید. فایل واقعی `.env.local` نباید commit شود.

## معماری فعال پایلوت

نسخه‌ای که اکنون به Supabase متصل است از schema عمومی `public` و این پنج جدول استفاده می‌کند:

- `public.sports_tenants`
- `public.sports_tenant_memberships`
- `public.sports_members`
- `public.sports_events`
- `public.sports_results`

در دیتابیس متصل، RLS روی هر پنج جدول فعال و FORCE شده است. سیاست‌ها دسترسی را بر اساس عضویت فعال، سازمان و نقش محدود می‌کنند. API نیز پیش از هر عملیات، کاربر و عضویت فعال او را بررسی می‌کند. شناسه سازمان ارسالی مرورگر به‌تنهایی مجوز دسترسی نیست.

Migrationهای `005_sports_os_namespaced.sql` و `006_sports_os_tenant_isolation.sql` طرح قدیمی‌تر و جداگانه‌ای برای schema با نام `sports_core` هستند و در runtime فعلی استفاده نمی‌شوند. آن‌ها را روی پروژه متصل اجرا نکنید؛ هر انتقال آینده باید با طرح مهاجرت مستقل، backup قابل بازیابی و تأیید مالک انجام شود.

## ورود و نقش‌ها

کاربر باید ابتدا از مسیر مورد اعتماد در Supabase Auth ساخته شود و سپس عضویت او توسط مالک/مدیر مجاز در جدول `sports_tenant_memberships` ثبت شود. ساخت ردیف مستقیم در `auth.users` از طریق SQL مجاز نیست.

| نقش ذخیره‌شده | دسترسی این نسخه |
|---|---|
| `owner` / `admin` | مشاهده اطلاعات سازمان، ثبت و مدیریت اعضا و رویدادها، ثبت و مشاهده نتایج |
| `referee` | مشاهده اعضا و رویدادها، ثبت و مشاهده نتایج؛ بدون مدیریت اعضا یا رویدادها |
| `coach` / `staff` / `member` | دسترسی به داده‌های عملیاتی مسدود است؛ پنل شخصی تا ایجاد پیوند امن حساب و پرونده ورزشکار فعال نمی‌شود |

اگر حساب به چند سازمان عضویت فعال داشته باشد، داشبورد فهرست سازمان‌های مجاز را نشان می‌دهد و کاربر یکی را انتخاب می‌کند. انتخاب اخیر فقط برای همان نشست مرورگر در `sessionStorage` نگهداری می‌شود و فقط وقتی بازیابی می‌شود که هنوز در فهرست عضویت‌های فعال برگشتی از سرور وجود داشته باشد. شناسه سازمان انتخاب‌شده در تمام درخواست‌های عملیاتی با هدر `x-tenant-id` ارسال می‌شود؛ هر درخواست API مجدداً هویت، عضویت فعال و نقش را سمت سرور بررسی می‌کند. تغییر سازمان، داده‌ها و انتخاب‌های فرم وابسته به سازمان قبلی را پاک می‌کند و پاسخ دیررس درخواست قبلی اجازه جایگزینی داده سازمان جدید را ندارد.

## مسیرهای اصلی

- `/login`: ورود
- `/`: داشبورد و انتخاب سازمان فعال
- `/api/core-sports/tenant`: فهرست سازمان‌های فعال کاربر
- `/api/core-sports/members`: فهرست و ایجاد عضو
- `/api/core-sports/events`: فهرست و ایجاد رویداد
- `/api/core-sports/results`: فهرست و ثبت نتیجه
- `/api/auth/logout`: خروج

## محدوده قابلیت‌های موجود

- ورود با Supabase Auth و نشست مبتنی بر cookie
- انتخاب سازمان از میان عضویت‌های تأییدشده
- کنترل نقش در API و RLS
- ثبت و مشاهده اعضا
- ثبت و مشاهده رویدادها
- ثبت و مشاهده نتایج پایه
- رابط فارسی و راست‌چین، واکنش‌گرا برای موبایل
- آزمون‌های ایستا و اعتبارسنجی دمو

## محدودیت‌ها و موارد تکمیل‌نشده

این نسخه هنوز شامل گردش‌کار کامل ثبت‌نام و تأیید ورزشکار، سرپرست و رضایت افراد زیر سن قانونی، مجوزها و مدارک مربیان/داوران، ثبت‌نام مسابقه، انتصاب عوامل، نتیجه موقت و نهایی، اعتراض، اصلاح نسخه‌دار نتیجه، بیمه، شهریه، حسابداری، تجهیزات، استعدادیابی، گزارش‌های محرمانه و پنل شخصی ورزشکار نیست.

همچنین آزمون واقعی با سه حساب مجزای مدیر، داور و ورزشکار و آزمون کامل دو کاربر در دو tenant هنوز اجرا نشده است. ساخت دو tenant به‌تنهایی اثبات جداسازی کامل دو tenant نیست.

تا پیش از تکمیل آزمون‌های مجوزدهی، بررسی مستقل امنیت و حریم خصوصی، MFA مدیران، حفاظت گذرواژه افشاشده، backup و بازیابی آزمایش‌شده و پذیرش رسمی پایلوت:
- از اطلاعات واقعی ورزشکاران، افراد زیر سن قانونی، بیمه یا امور مالی استفاده نکنید.
- پرداخت واقعی را فعال نکنید.
- این نسخه را production-ready یا دارای تأیید امنیتی مستقل معرفی نکنید.

وضعیت دقیق و شواهد جاری در `LIVE_IMPLEMENTATION_STATUS.md` ثبت می‌شود.
